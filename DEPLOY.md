# DEPLOY — getting AtomPub live on a real URL

This walks you through publishing the journal in three modes, from
zero-to-something in ~10 minutes.

---

## Mode 1 · GitHub Pages on the default subdomain (fastest)

You'll get a live URL at `https://<your-org>.github.io/AtomPub/`.

```bash
# 1 · create the repo on GitHub (web UI), then:
git init
git add .
git commit -m "AtomPub v0.4 — Quarto journal + React prototype"
git branch -M main
git remote add origin git@github.com:AtomRearch/AtomPub.git
git push -u origin main
```

Then in the GitHub web UI:

1. **Settings → Pages → Build and deployment → Source → GitHub Actions**
2. Wait for the **Publish AtomPub** action to finish (~3 min).
3. Visit the URL shown at the top of the Pages settings.

After the first deploy, every `git push origin main` re-renders the site.

---

## Mode 2 · Custom domain (`atompub.org`-style)

Once Mode 1 works:

1. Add a `CNAME` file at the **repo root** with one line: `atompub.example.com`.
2. At your DNS provider, add a `CNAME` record from `atompub.example.com` → `<your-org>.github.io`.
3. In **Settings → Pages → Custom domain**, paste `atompub.example.com` and tick **Enforce HTTPS**.

GitHub Pages handles TLS automatically via Let's Encrypt.

---

## Mode 3 · Local-only preview (for development)

```bash
cd journal
quarto preview
```

Open `http://localhost:3434`. Edit any `.qmd` and the browser refreshes
automatically.

For PDF output:
```bash
quarto install tinytex          # one-time, ~200MB
quarto render articles/evaporating-moat.qmd --to atompub-light-pdf
```

## Troubleshooting

**"Format atompub-light-html not found"**
The extension is in `journal/_extensions/atompub-light/`. Quarto only finds
extensions that live under a `_extensions/` folder *inside the project root*
(which is `journal/`). Don't move it.

**Fonts not loading in the rendered site**
`theme.scss` imports Fraunces + Inter + JetBrains Mono + Caveat from Google
Fonts. If GitHub Pages is behind a firewall that blocks Google Fonts,
self-host the WOFF2 files in `journal/assets/fonts/` and rewrite the `@import`
at the top of `theme.scss` to point at them.

**The React prototype links from the journal (`/AtomPub.html`) 404**
That's the `publish.yml` workflow's copy step. Check that step ran successfully
in the Actions log. The prototype's static files need to land inside
`journal/_site/` before the Pages artifact is uploaded.

**PDF render fails in Actions with "xelatex: command not found"**
The workflow installs TinyTeX via `r-lib/actions/setup-tinytex@v2`. If that
ever breaks, swap to `quarto-dev/quarto-actions/setup@v2` followed by
`quarto install tinytex --no-prompt`.

## What gets deployed

Everything under `journal/_site/` after `quarto render`, plus the prototype's
static files copied alongside. Specifically:

- `index.html`, `about.html`, `bench.html`, `sprints.html`, `submit.html`
- `articles/index.html` (the listing) and one HTML per article
- One PDF per article that opted into `atompub-light-pdf` format
- `articles/index.xml` (RSS feed)
- `AtomPub.html` and friends (the React prototype, for the dashboard)
- `assets/` (logo, OG cards)
- `robots.txt`, `sitemap.xml` (auto-generated by Quarto)
